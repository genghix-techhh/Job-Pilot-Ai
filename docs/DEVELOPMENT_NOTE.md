## Decisions worth knowing

- **Table name** `job_postings` (model `JobPosting`) instead of `jobs`, which Laravel's queue already uses.
- **`notification_logs`** instead of `notifications` (avoids Laravel's database-notification table).
- **Settings** are key/value rows (`settings`) layered over `config/jobpilot.php` defaults; scoring caches record a hash of the weights/thresholds so changes re-score automatically.
- **AI is optional at every step.** The rule-based score, drafts and tracking never need Gemini; AI refines duties/project fit (blended 50/50 with a keyword check so it can't dominate) and wording.
- **Submission gateway seam** (`SubmissionGateway`) exists only so the approval/idempotency rules live in one place; none is registered because no authorised integration exists for the supported sources.
- `applications.job_id` is `RESTRICT` — deleting a source can never silently erase application history.

## Advanced pass — decisions

- **Matching v2** is still fully local and explainable. `RequirementSplitter` separates required from "nice to have" text; skills weigh title ×2 / required ×1 / preferred ×0.5. `IdfIndex` (TF-IDF over stored jobs, cached 6 h, only used with ≥ 25 jobs, invalidated when a sync adds jobs) feeds a cosine similarity. Raw similarity of CV-vs-posting is small, so it is mapped with `sqrt(sim / 0.10)` — calibrated on ~350 real postings (linear scaling topped out at 29 %).
- **Exclusion rules** never delete or hide the score: a job is scored, stored with `job_matches.exclusion` (the reason), and filtered out of feed/dashboard/alerts/AI. Keywords are whole-word; a `title:` prefix restricts the match to the title (a bare word such as "manager" also matches boilerplate like "reporting to the manager").
- **Digest** runs from the hourly scheduler entry `app:send-digest`; it is due when the owner's local hour matches `digest_hour` and nothing was sent in the period. It reuses the alert pipeline (dedupe, retry, logging).
- **Follow-up messages** are suggestions to copy — the app never sends mail to employers.
- **PDF** is generated by dompdf with remote resources, PHP and JS disabled; the document is the same hashed content the approval gate covers.
- **Interview prep** only cites evidence that exists in the stored profile; AI refinement is validated the same way as drafts.
- **Data export** contains profile, applications, events, interviews and settings — never API keys, OAuth tokens or CV files.
- Upgrade note: run `php artisan migrate` (adds `job_matches.exclusion` and `saved_searches`), then optionally `php artisan app:recalculate-matches --force` to re-score with v2.

## Bugs the live/real-world checks found (all fixed, with tests where practical)

- Guzzle's `stream` option forced the stream handler, which cannot pin connections (`CURLOPT_RESOLVE`) — mocked tests passed, the live fetch failed. Size cap now uses curl callbacks.
- Remote OK serves double-encoded text; a guarded repair was added.
- Default seeder created a user (violating "no default password"); `ProfileService::forUser` could double-create a profile; a missing `use ($gateway)` in the submission transaction; screening-question edits were wrongly treated as letter edits.
- Consent copy over-promised ("employer names never sent") — corrected to match behaviour.
